# Architecture

A FastAPI server on 127.0.0.1 serves static pages and a JSON API. There is **no build step**: the
browser loads ES modules from `web/` as they are. Files are the database for the DAW; the
generator uses SQLite.

## Backend (`tunelab/`)
| File | Role |
|---|---|
| `server.py` | Assembles the app: pages, routers, error mapping, host check |
| `routes_daw.py` | API: library, settings, notation conversion, scoring |
| `routes_generator.py` | API: generate, list, score typed notation |
| `documents.py` | **DAW file formats** (pydantic) and conversion to and from `notation.Tune` |
| `library.py` | File storage: atomic writes, ids, revisions, favorites, trash, settings |
| `notation.py` | Text notation and the `Tune` object used by generator, scorer, extractor |
| `generator.py`, `scorer.py`, `pipeline.py`, `check.py` | Generate, score, flag, test the scorer |
| `extract.py`, `synth.py` | Audio to melody; offline synth for tests |
| `db.py` | SQLite of generated tunes (`data/tunes.db`) |

## Frontend (`web/`)
| File | Role | Touches the page? |
|---|---|---|
| `daw/model.js` | Notes, tracks, projects: pure operations | no |
| `daw/tempo.js` | Tempo repair: pure operations | no |
| `daw/store.js` | State, undo/redo, dirty tracking | no |
| `daw/midi.js` | MIDI conversion | no |
| `daw/shortcuts.js` | Action list, default keys, key capture | no |
| `daw/roll.js` | Piano roll: drawing, gestures, zoom (Konva) | yes |
| `daw/player.js` | Playback (Tone.js) | audio |
| `daw/panels.js` | Toolbar, track list, note inspector | yes |
| `daw/files.js` | Open, save, import, export flows | dialogs |
| `daw/library.js`, `settings.js`, `tools.js` | The three dialogs | yes |
| `daw/main.js` | Wiring: actions, keyboard, buttons | yes |
| `generator/` | The Tune Generator page | yes |
| `shared/` | DOM and API helpers, base styles, colors | |
| `vendor/` | Pinned third-party builds, generated by `npm run vendor`; never edit | |

Libraries: **Konva** (canvas, hit testing, `Transformer` resize handles), **Tone.js** (transport,
synths), **@tonejs/midi**, **tinykeys**. All MIT; licenses sit in `web/vendor/`.

## Core concepts

**Two time units.** `notation.py` uses 12 ticks per beat; the DAW uses `PPQ = 480`. One notation
tick is 40 DAW ticks (`documents.SCALE`). The DAW is finer so that scaled groups and imported MIDI
keep their shape. Converting DAW to notation can round, and fails on overlaps. A beat is always a
quarter note. `PPQ`, `MAX_TICK` and the allowed sounds, modes and meters are defined in both
`documents.py` and `model.js` and must agree.

**Immutable projects.** Operations in `model.js` return new objects, and return the *same* array
when nothing changed. Undo is a list of earlier project objects; "unsaved" means
`state.project !== state.saved`. Never modify a note, track or project in place.

**Ids.** Note and track `id`s exist only in the session and are stripped when saving.

**Data flow.** Input -> `store.commit(...)` -> every subscriber re-reads the state. `store.set`
changes view state (tool, grid) without an undo step.

**Gestures.** `roll.js` runs one gesture at a time, previewing by moving Konva shapes. Only `end()`
commits, so a drag is one undo step. Any store change redraws, which cancels a running gesture.
Shortcuts other than Escape are ignored during a drag.

**Group scaling.** Konva's Transformer supplies the handles; `boundBoxFunc` turns the dragged edge
into one factor, limited by `limitFactor`; `scaleNotes` applies it. Starts and ends are rounded,
never lengths, so touching notes stay touching.

**Roll coordinates.** The stage is only as large as the visible area and stays put (sticky) while a
large empty div scrolls. Layers are shifted by the scroll offset. `ox()`/`oy()` give time 0 and
pitch 127.

**Playback.** The transport counts in DAW ticks. Note or tempo changes while playing reschedule
everything. `active` is our own flag because the transport starts slightly in the future.

**Panels update in place** rather than being rebuilt, so that redraws never steal focus from a
field being typed in. `setValue` skips the focused field.

## Files on disk
`library/` (or `$TUNELAB_LIBRARY`): `projects/<id>.json`, `melodies/<id>.json`, `favorites.json`,
`settings.json`, `trash/`. Formats are the models in `documents.py`; unknown fields are rejected
and `version` is 1. Saving sends the revision (content hash) that was opened; a mismatch is
HTTP 409 and the user is asked. The generator's database is `data/tunes.db` (or `$TUNELAB_DB`).

## Tests
| Command | Covers |
|---|---|
| `uv run pytest` | Everything in Python, including the browser tests below |
| `uv run pytest tests/test_e2e.py` | Real mouse and keyboard in Chrome |
| `uv run pytest tests/test_monkey.py` | Random input, checking invariants after each step |
| `npm test` | Pure JS modules (needs `npm install --ignore-scripts` once) |
| `uv run tunelab-check` | Quality of the scorer |

Tests use temporary folders through the environment variables above and never touch user data.
In the page, `window.tunelab` exposes store, roll, player and actions for tests and debugging.
